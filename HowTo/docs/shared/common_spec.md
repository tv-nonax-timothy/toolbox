# システム共通仕様書

## 1. 共通データ型定義

### 1.1 ユーザー ID（user_id）
- **型**: `string` (UUID v4)
- **制約**: 8 文字以上、英数字混合
- **用途**: 全機能で一意の識別子として使用

### 1.2 ステータスフラグ
- **型**: `enum`
- **値**: `"active"`, `"inactive"`, `"pending"`
- **デフォルト**: `"pending"`

## 2. API コントラクト共通ルール

### 2.1 レスポンスフォーマット
```json
{
  "success": boolean,
  "message": string,
  "data": object | null,
  "error_code": string?
}
```

### 2.2 エラーコード一覧
- `E001`: 認証失敗
- `E002`: 権限不足
- `E003`: リソース不存在
- `E999`: サーバーエラー

## 3. セキュリティ要件

### 3.1 パスワードポリシー
- **最小文字数**: 8 文字
- **必須要素**: 大文字、小文字、数字、記号（各 1 つ以上）
- **保存形式**: bcrypt ハッシュ化（cost=12）

### 3.2 セッション管理
- **有効期限**: 24 時間
- **再認証**: 3 回失敗したら 5 分間ロック

## 4. ロギング要件

### 4.1 ログレベル
- `INFO`: 正常な処理フロー
- `WARN`: 予期せぬ状況だが回復可能
- `ERROR`: 処理失敗、エラー発生
- `DEBUG`: デバッグ情報（開発環境のみ）

### 4.2 ログフォーマット
```json
{
  "timestamp": "ISO8601",
  "level": "INFO|WARN|ERROR",
  "service": string,
  "message": string,
  "trace_id": string?
}
```

## 5. パフォーマンス目標

### 5.1 レスポンスタイム
- API: 200ms 以内（95%）
- ページ読み込み：300ms 以内

### 5.2 スケーラビリティ
- 同時接続数：10,000 以上
- DB クエリ：インデックス化済み

## 6. データベース共通制約

### 6.1 文字コード
- **全テーブル**: UTF-8
- **コラレーション**: `utf8mb4_unicode_ci`

### 6.2 外鍵制約
- カスケード削除：`ON DELETE CASCADE`（子テーブル）
- セット NULL: `ON SET NULL`（オプションフラグ）
