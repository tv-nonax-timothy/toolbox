1. アーキテクチャ・コンセプト

本プロジェクトは、GitHub Copilotのカスタムエージェント機能（.github/agents/）を活用し、 「堅牢なウォーターフォール型ドキュメント管理」と「迅速なアジャイル並列実装」を融合させた開発フレームワークです。

  • 適材適所のモデル選定: 高度な推論やコンテキスト理解が必要な上流・設計工程には Claude 3.5 Sonnet を、スピードと実装精度が求められる製造工程には GPT-4o を割り当て最適化。
  • 直列・並列のハイブリッド制御: 整合性が重要な要件・外部設計は単一エージェントで直列に、独立した機能開発（内部設計・実装）は複数サブエージェントで同時並行処理。
  • 明確なコンテキスト分離: エージェントごとに読み書き権限と参照ドキュメントを分離し、コンテキスト汚染やファイルの競合・事故を防止。

2. エージェント定義一覧（.github/agents/）

定義ファイル 役割（ロール） モデル 処理モード 概要
coordinator.agent.md リード（PM） claude-3.5-sonnet オーケストレーション 全体の進捗管理、タスク分解、サブエージェントの自動呼び出しと成果物統合。
requirements-lead.agent.md 要件定義 claude-3.5-sonnet 直列・1人 全体方針を踏まえた要件定義書の策定・更新。
external-designer.agent.md 外部設計 claude-3.5-sonnet 直列・1人 画面遷移図、DBスキーマ、共通UI仕様の策定。
internal-designer.agent.md 内部設計 claude-3.5-sonnet 並列・複数 共通テンプレートに基づき、機能ごとの詳細設計を並列生成。
developer-worker.agent.md 製造・単体テスト gpt-4o 並列・複数 内部設計書に基づき、ソースコードおよび単体テストコードを並列実装。
system-tester.agent.md システムテスト claude-3.5-sonnet 直列・1人 要件および外部設計を満たす結合・システムテスト仕様書の策定。
qna-assistant.agent.md 質問対応 claude-3.5-sonnet 読み取り専用 仕様書全般を参照し、開発者の疑問や仕様問い合わせに回答。

3. ドキュメント構造（docs/）

エージェント間が迷わずデータを受け渡せるよう、成果物のディレクトリ構造を厳格に定めています。

docs/
├── 1_requirements/         # 要件定義書
├── 2_external_design/      # 外部設計（画面遷移、DB、UI）
│   ├── db_schema.md        # DB スキーマ
│   ├── screen_flow.md      # 画面遷移図
│   └── common_ui_spec.md   # 共通 UI 仕様
├── 3_internal_design/      # 機能別内部設計書（並行生成）
├── 5_system_test/          # システムテスト仕様書
└── shared/                 # 共有リソース・共通テンプレート
    ├── common_spec.md      # 共通仕様書
    ├── design_template.md  # 内部設計テンプレート
    └── master_workflow.md # マスターワークフロー（リード用）

4. 使い方（VS Code Copilot Chat）

リードエージェントへの指示例

VS Codeの Copilot Chat で @coordinator を呼び出し、まとめて並行タスクを指示します。

@coordinator docs/shared/master_workflow.md に基づいて、
新規機能「ユーザー認証フェーズ」の要件定義から内部設計までを順次進めてください。
内部設計の作成段階では、機能ごとに並列サブエージェントを起動して処理してください。
