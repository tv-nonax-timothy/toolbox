GitHub copilotでサブエージェントとリードエージェントを使いたい

GitHub Copilotでは、リードエージェント（コーディネーター）が全体の管理やタスク分解を行い、専門特化したサブエージェント（ワーカー）に作業を並行・分担させるマルチエージェント構成（Agentic Workflows）を利用できます。これにより、大規模なリファクタリング、複数ファイルへの機能追加、コードレビューなどを効率的に自動化できます。   
Awesome GitHub Copilot - GitHub

以下に、VS CodeやCopilot CLIなどの環境でサブエージェントとリードエージェントを設定・活用するための基本的な仕組みと手順を解説します。

1. 仕組みの概要
リードエージェント（Coordinator / Main Agent）: 全体の文脈を把握し、ユーザーからの指示を分析してタスクを計画・分解します。自分で直接コードを書き換えるだけでなく、必要に応じてサブエージェントを呼び出します。   
Awesome GitHub Copilot - GitHub

サブエージェント（Subagent / Worker）: 特定の狭いスコープ（例：リサーチ、テスト生成、特定のセキュリティレビューなど）に特化した一時的なワーカーです。それぞれ独立したコンテキストウィンドウを持ち、並行して処理を実行します。   
AgentPatterns.ai

2. 設定方法（カスタムエージェントの定義）
プロジェクト内（通常は .github/agents/ ディレクトリなど）に、Frontmatter（メタデータ）を含むMarkdownファイルとしてエージェントを定義します。   
Awesome GitHub Copilot - GitHub

① リードエージェントの例 (feature-coordinator.agent.md)   
Awesome GitHub Copilot - GitHub
リードエージェントには、ツール（agent）を許可し、呼び出せるサブエージェントを agents プロパティのホワイトリストで指定します。   
Awesome GitHub Copilot - GitHub

Markdown
---
name: Feature Coordinator
tools: ['agent', 'read', 'search', 'edit']
agents: ['Planner', 'Implementer', 'Reviewer']
---

あなたは機能開発を統括するリードエージェントです。ユーザーの要望を受け取り、作業を分解してサブエージェントに指示を出し、最終的な成果物を統合してください。
② サブエージェントの例 (planner.agent.md など)
サブエージェント側では、ユーザーから直接選択されないように user-invocable: false（または他のコーディネーターからのみ呼び出せる設定）にすることが一般的です。   
Awesome GitHub Copilot - GitHub

Markdown
---
name: Planner
user-invocable: false
tools: ['read', 'search']
---

あなたは計画担当のサブエージェントです。既存のコードパターンを調査し、実装のための詳細なステップを提案してください。
3. 実際の使い方とプロンプトのコツ
エージェントを定義したら、Copilot Chat（Agentモードなど）やCLI環境から呼び出します。

並行タスクや分割を意識したプロンプトを与える
ただ「機能を実装して」と頼むよりも、以下のように役割を意識したプロンプトを書くと、リードエージェントが自動的にサブエージェントへタスクを振り分けやすくなります。

プロンプト例:
「以下の機能要件について並行して進めてください：

既存コードのパターン調査   
Awesome GitHub Copilot - GitHub

実装計画の策定

セキュリティリスクの洗い出し
上記をそれぞれ分析し、最終的な推奨プランにまとめてください。」   
Awesome GitHub Copilot - GitHub

Copilot CLIの /fleet などの活用
ターミナル環境や対応する拡張機能では、複雑なタスクを複数のサブエージェントに同時に（バックグラウンドで）割り振って実行させることができます。   
The GitHub Blog

💡 運用上のポイント・注意点
ファイルシステムの共有: サブエージェントは同じファイルシステムを共有するため、同じファイルを同時に別のサブエージェントが書き換えないようにタスクを分割（パーティショニング）することが重要です。   
The GitHub Blog

コンテキストの独立: 各サブエージェントは個別のコンテキストウィンドウを持つため、リードエージェントの会話履歴は直接見えません。プロンプトには必要な情報を自己完結的に含める必要があります。   
The GitHub Blog

vscodeからでも使える？

はい、VS Codeから完全にご利用いただけます！

GitHub Copilotのマルチエージェント機能（リードエージェントとサブエージェントの連携）は、VS Code上の拡張機能を通じて、主に以下の2つのアプローチで活用できます。

1. VS Codeの「Copilot Chat (Agent モード)」を活用する
VS Codeの拡張機能「GitHub Copilot Chat」では、Agentモード（あるいは @workspace などの参加機能）を利用して、AIに一連のタスクを自律的に判断・実行させることができます。

仕組み:
VS CodeのチャットパネルでAgentモードを有効にし、複雑な指示（例：「この機能の実装計画を立てて、関連ファイルを特定し、テストコードまで作成して」）を与えると、Copilotが内部で役割を切り替えながら（あるいは設定したカスタムエージェントを呼び出しながら）ステップを踏んで作業を進めます。

メリット:
追加の複雑なセットアップをほとんどしなくても、VS Codeのエディタ画面、ターミナル、ファイルシステムと連携しながら動いてくれます。

2. カスタムエージェント（.github/agents/）の定義
プロジェクトごとに、前述したようなリードエージェントやサブエージェントの定義（Markdownファイル）をリポジトリ内に配置しておくと、VS CodeのCopilot Chatからそれらのカスタムエージェントを直接指名して呼び出すことができます。

設定手順の概要:

プロジェクトのルートに .github/agents/ ディレクトリを作成する。

リード用とサブ用の .agent.md ファイルを配置する。

VS CodeのCopilot Chatで @エージェント名 のように入力して呼び出す、または指示を出すことで、定義した通りのマルチエージェント体制でコード生成やリファクタリングを行わせる。

VS Code上ですでにGitHub Copilot Chatを使われている環境であれば、まずはAgentモードで複雑なタスクをお願いするか、リポジトリにカスタムエージェントの設定を追加して試してみてください！

並行でサブエージェントを動かす事も可能か？

はい、複数のサブエージェントを並行（同時）に動かすことは完全に可能です。   
wearecommunity.io

VS CodeのGitHub Copilotにおけるマルチエージェント環境では、リードエージェントが複数の独立したタスクを判断し、複数のサブエージェントに振り分けて並行実行させることができます。   
wearecommunity.io

並行実行の仕組みや、活用するためのポイントは以下の通りです。

1. 並行実行のメリット
コンテキストの分離（Context Hygiene）: それぞれのサブエージェントが独立した別のコンテキストウィンドウ（作業スペース）で動作するため、大量のファイルを読み込ませるような泥臭い中間作業（調査やログ解析など）のゴミが、メインのチャット画面や他のタスクに混ざりません。   
wearecommunity.io

時間の短縮: 独立した複数のタスク（例：「セキュリティ脆弱性のチェック」「ドキュメントの整合性確認」「特定パターンのリサーチ」など）を同時に走らせることで、処理時間を大幅に短縮できます。   
wearecommunity.io
他 1 件

2. 並行実行させるためのプロンプトのコツ
リードエージェントに対して、「並行して（同時に）進めるべきタスク」であることを自然言語で明示的に伝えると、複数のサブエージェントへ効率よく作業が割り振られます。   
wearecommunity.io

プロンプトの例:
「以下の3つのアプローチについて、それぞれ独立したサブエージェントを使って並行で調査・比較してください：   
wearecommunity.io

パフォーマンス重視の実装案の検討

メモリ効率重視の実装案の検討

セキュリティリスクの洗い出し
終わったら、リード側で結果を統合して最適なプランを提案して。」   
Awesome GitHub Copilot - GitHub

3. 注意点（ファイルの競合）
ファイルシステムの共有: サブエージェントは同じプロジェクトのファイルシステムを共有して動作します。そのため、まったく同じファイルを複数のサブエージェントが同時に書き換えないようにタスクを分割・制御することが重要です（書き込みが競合する恐れがあるため、調査や別々のファイルの編集など、競合しないタスクの並行化に向いています）。

開発アイテムが多い場合、コーダーエージェントを複数設定して同時に動かす事も可能？

はい、開発アイテム（タスク）が複数ある場合、複数のコーダーエージェント（サブエージェント）を動的に設定して同時に並行稼働させることは十分に可能です。   
Arvind Khadye

GitHub Copilotのマルチエージェント機能やCLIの /fleet コマンド、あるいはVS Codeのエージェント機能を組み合わせることで、大規模なタスクを分担・同時並行処理させることができます。   
The GitHub Blog

開発アイテムが多い現場で、複数エージェントを同時に動かす仕組みや、成功させるための重要なポイントは以下の通りです。   
Arvind Khadye

1. どのように同時に動くのか？
オーケストレーション（総括）:
リードエージェント（または /fleet などの司令塔）が全体の開発アイテム（要件）を受け取り、「どのタスクとどのタスクが独立しているか（依存関係がないか）」を分析・分解します。   
Arvind Khadye

サブエージェントへの自動ディスパッチ:
依存関係のない独立したタスク（例：「Aコンポーネントの実装」「Bコンポーネントのテスト作成」「Cのドキュメント更新」など）を、それぞれ個別のコンテキストを持つサブエージェントに同時に割り当てます。   
Arvind Khadye

結果の統合:
それぞれのサブエージェントがバックグラウンドで並行作業を終えると、リードエージェントが成果物を回収・統合します。   
Arvind Khadye

2. 同時並行させるための具体的な設定・指示のコツ
複数のコーダーエージェントをスムーズに同時稼働させるためには、以下の点に気を配ると効果的です。

担当ファイルの境界を明確にする（ファイル競合の防止）
サブエージェントたちは同じファイルシステムを共有して動きますが、ファイルロック機構などは持っていません。そのため、「同じファイルを複数のエージェントが同時に書き換えないようにタスクを明確に分ける」ことが最大の鉄則です。   
The GitHub Blog
他 1 件

良い分割例:

エージェント1: src/components/Header.tsx の実装を担当

エージェント2: src/api/client.ts の実装を担当

エージェント3: tests/e2e/auth.spec.ts のテスト作成を担当

カスタムエージェントに「コーダー」としての役割を定義する
あらかじめ .github/agents/coder.agent.md のように、実装に特化したサブエージェントを定義しておくと、リード側から指名して大量の実装タスクを効率よく処理させることができます。   
Arvind Khadye

💡 運用上の注意点
大量の開発アイテムを一気に並行処理させると非常にスピーディですが、AIが生成したコード同士のインターフェースの噛み合わせ（型定義の微妙なズレなど）が起きる場合があります。そのため、「実装は並行して複数のサブエージェントにやらせ、最後の結合・ビルド確認・レビューだけはメインのリードエージェント（または人間）が厳しくチェックする」という役割分担にするのが、最もトラブルが少なく効率的な進め方です。

サブエージェントを指定したAIモデルで動くようにできるか？　モデル毎の得意分野を任せたい

はい、GitHub Copilotのカスタムエージェント機能では、エージェント（サブエージェント含む）ごとに使用するAIモデルを個別に指定することができます。   
Awesome GitHub Copilot - GitHub

これを利用して、「論理的な推論やリサーチが得意なモデル」や「コードの高速コーディング・修正が得意なモデル」など、タスクの性質に合わせてモデルを使い分けることが可能です。   
GitHub Docs

1. モデルを指定する方法（Frontmatterの設定）
カスタムエージェントの定義ファイル（.agent.md）のヘッダー部分（YAML Frontmatter）にある model: プロパティに、利用したいモデル名を設定します。   
Visual Studio Code

例：アーキテクチャ設計やリサーチ用（推論・分析が得意なモデルを指定）
Markdown
---
name: Architect Planner
model: claude-3.5-sonnet  # またはプロジェクトで利用可能なモデルID
tools: ['read', 'search']
user-invocable: false
---

あなたは設計・リサーチ担当のサブエージェントです。既存のコードベースを詳細に分析し、実装計画を立案してください。
例：定型的なコーディング・ファイル修正用（速度やコード生成が得意なモデルを指定）
Markdown
---
name: Fast Coder
model: gpt-4o  # またはタスクに適したモデル
tools: ['read', 'edit', 'write']
user-invocable: false
---

あなたは実装担当のサブエージェントです。指示された仕様に基づいて、迅速かつ正確にコードの記述・修正を行ってください。
※指定できるモデル名は、お使いの環境（GitHub Copilotのプランや組織で有効化されているモデル）によって異なります。未指定の場合は、チャット画面側で選択しているデフォルトのモデルが引き継がれます。

2. 得意分野を活かしたマルチエージェント運用のコツ
モデルごとの特性（「長文脈の理解や複雑な設計」「正確な構文生成」など）に合わせてサブエージェントを分けると、以下のような効果的な分業体制が作れます。

リサーチ・設計フェーズ（頭脳派モデル）

複雑な依存関係の調査や、全体のアーキテクチャ設計を行うサブエージェントに、推論能力の高いモデルを割り当てる。

実装・テスト作成フェーズ（スピード・コード生成派モデル）   
GitHub Docs

決まった仕様に基づいた細かなコーディングやユニットテストの量産を行うサブエージェントに、高速なモデルを割り当てる。
