💡 アーキテクチャのコンセプト

GitHub Copilotのカスタムエージェント機能（.github/agents/）を活用し、 「堅牢なドキュメント管理」と「柔軟な並列AI実装」を両立させた構成です。

  • 適材適所のモデル選定: 高度な推論が得意な Claude 3.5 Sonnet と、スピード感のある実装が得意な GPT-4o を役割ごとに使い分けます。
  • 直列・並列のハイブリッド処理: 仕様のブレを防ぐ上流工程は単一エージェント（直列）で、機能ごとの設計・製造は複数エージェント（並列）で一気に進行します。
  • 安全なファイル管理: 各エージェントのアクセス範囲を明確に限定し、コードや設計書の予期せぬ書き換えを防止します。

このガイドでは、リードエージェントとサブエージェントの連携方法、直列・並列処理の使い分け、安全なファイル管理の実装例を紹介します。 なお、個人的な利用を前提としており、実際の企業様向けプロジェクトや大規模のチームでの運用には適さない場合があります。導入される場合は十分に検討の上、自己責任で行ってください。

🛠️ エージェント定義一覧（.github/agents/）

定義ファイル 役割（ロール） モデル 処理モード 役割の概要
coordinator.agent.md リード（PM） Claude 3.5 Sonnet オーケストレーション 全体の進行管理、タスクの分解、サブエージェントの呼び出しと統合。
requirements-lead.agent.md 要件定義 Claude 3.5 Sonnet 直列・1人 全体の方向性を整理し、要件定義書を作成・更新。
external-designer.agent.md 外部設計 Claude 3.5 Sonnet 直列・1人 画面遷移図、DBスキーマ、共通UI仕様を作成。
internal-designer.agent.md 内部設計 Claude 3.5 Sonnet 並列・複数 共通テンプレートに沿って、機能別の詳細設計を並行して作成。
developer-worker.agent.md 製造・単体テスト GPT-4o 並列・複数 内部設計書に基づき、ソースコードとテストコードを並行実装。
system-tester.agent.md システムテスト Claude 3.5 Sonnet 直列・1人 全体の要件と外部設計を満たすテスト仕様書を作成。
qna-assistant.agent.md 質問対応 Claude 3.5 Sonnet 読み取り専用 仕様書全般を参照し、質問や不明点に回答（ファイル変更なし）。

📁 ドキュメントフォルダ構造（docs/）

各エージェントがスムーズに成果物を受け渡せるよう整理されたフォルダ配置です。

docs/
├── 1_requirements/         # 要件定義書
├── 2_external_design/      # 外部設計（画面遷移、DB、UI）
│   ├── db_schema.md        # DB スキーマ
│   ├── screen_flow.md      # 画面遷移図
│   └── common_ui_spec.md   # 共通 UI 仕様
├── 3_internal_design/      # 機能別内部設計書（並行生成）
├── 5_system_test/          # システムテスト仕様書
└── shared/                 # 共有リソース・共通テンプレート
    ├── common_spec.md      # 共通仕様書
    ├── design_template.md  # 内部設計テンプレート
    └── master_workflow.md # マスターワークフロー（リード用）

🚀 VS Code での呼び出し例

VS Codeの Copilot Chat で @coordinator を呼び出し、タスクを一気に依頼します。

@coordinator docs/shared/master_workflow.md に基づいて、
「ユーザー認証機能」の要件定義から内部設計までを進めてください。
内部設計のフェーズでは、機能ごとに並列サブエージェントを起動して処理してください。
